# ADR-0005: 인증/인가 전면 통합 — 기본 차단 + 도메인 소유권

- 상태: 수락됨
- 날짜: 2026-07-30
- 관련: ADR-0002(헥사고날), ADR-0004(도메인 순수화), `orchestration/API-CONTRACT.md` §1

## 배경

인증 마이그레이션은 Phase 3a(듀얼리드)에서 멈춰 있었다. 실측한 현재 상태:

- `RoleInterceptor`는 **`@RequireRole`이 붙은 엔드포인트만** 검사하고, 무토큰 요청은 통과시킨다.
- 12개 컨트롤러 중 7개에 `@RequireRole`이 없다. 그중 `GET /lectures/{lectureId}/enrollments`는 수강생 명단이 무인증으로 노출된다.
- `GET /sse-stream/{memberId}`는 경로 변수로 **남의 알림 스트림을 구독**할 수 있다.
- 식별자를 `@Auth(required=false)`(11곳) + `AuthIdentities.resolve`(9곳)로 토큰·쿼리파라미터 이중 수용한다.

계약 문서는 Phase 3b 게이트 사유를 "클라이언트가 아직 토큰을 안 보냄"으로 기록했으나, **클라이언트 소스 확인 결과 그 전제가 이미 해소됐다**:

| 확인 항목 | 근거 |
|---|---|
| 안드로이드가 모든 요청에 Bearer 부착 | `AuthInterceptor.kt` — OkHttp 등록, 401 시 세션 정리 |
| 안드로이드 SSE도 인증 인터셉터 경유 | `SseClient`가 qualifier 없는 기본 `OkHttpClient` 주입 + `newBuilder()`는 인터셉터 승계 |
| 안드로이드 전 화면 로그인 게이트 | `AppNavHost.kt:66` — 비인증 시 `Route.Login` |
| 웹 전 화면 로그인 게이트 | `app/page.tsx:139` — `accessToken` 없으면 로그인 |
| 웹은 SSE 미사용 | `EventSource`/`sse-stream` grep 0건 |

즉 "네이티브 EventSource는 헤더를 못 보낸다"는 SSE 예외 사유도 **현재 클라이언트 실태와 맞지 않는다**.

## 결정

### 1. 기본 차단 + 화이트리스트 (fail-safe)

인증 게이트를 **모든 요청에 적용**하고, 공개 엔드포인트만 명시적으로 연다. 화이트리스트는 `POST /login`, 회원가입 3종(`POST /students|/tutors|/parents`), `/internal/**`(별도 API 키 필터가 담당).

기존처럼 어노테이션이 붙은 곳만 검사하면(fail-open) 새 엔드포인트를 추가할 때마다 사람이 기억해야 하고, 빠뜨리면 조용히 무방비가 된다. 실제로 그렇게 7개가 방치됐다. 기본을 차단으로 뒤집으면 그 실수가 구조적으로 불가능해진다.

### 2. 소유권 인가는 도메인 공개 메서드

"이 강의의 강사만 수락할 수 있다"는 **도메인 불변식**이므로 애그리거트가 스스로 지킨다. `Lecture`/`SpecialLecture`의 private `validateTutorAuthority`를 의도 드러내는 공개 메서드로 승격하고, 서비스는 호출만 한다.

현재 `LectureEnrollmentService`는 `lecture.getTutorId()`를 꺼내 비교한다(Tell-Don't-Ask 위반). 같은 규칙이 도메인에 이미 존재하는데 private이라 재사용하지 못해 **중복 구현**된 상태다. 인가를 전면 적용하면 이 패턴이 엔드포인트 수만큼 복제되므로 지금 바로잡는다.

**역할 인가(RBAC)는 도메인이 아니다.** "STUDENT는 강의를 만들 수 없다"는 전송 계층 정책이므로 `@RequireRole` 인터셉터에 남긴다. 두 관심사를 섞지 않는다.

### 3. SSE는 경로 변수를 제거하고 `/sse-stream` 신설

식별자를 토큰에서만 얻는다. 경로 변수는 계약에서 사라지므로 오용 자체가 불가능해진다. BE와 안드로이드를 같은 작업에서 교체한다 — 스토어 배포 전이라 구버전 호환이 불필요하다.

### 4. 레거시 식별자 파라미터는 수용하되 무시

`studentId`/`tutorId`/`memberId` 쿼리 파라미터는 시그니처에 남기되 값을 쓰지 않는다. 클라이언트를 깨지 않으면서 IDOR는 즉시 차단된다. 파라미터 제거(완전 Phase 3b)는 클라이언트 3종 동시 릴리스가 필요하므로 별도 결정으로 미룬다.

## 결과

- 무인증 노출(수강생 명단)과 SSE IDOR가 닫힌다.
- 새 엔드포인트는 기본이 보호 상태다.
- 소유권 규칙이 도메인 한 곳에 모여 중복이 사라진다.
- 클라이언트는 SSE URL 외에 변경이 없다.

## 검토한 대안

- **어노테이션 확대(기본 허용 유지)** — 변경은 작지만 fail-open이 그대로 남아, 이번에 고치는 사고가 다음에 재발한다.
- **Spring Security 도입** — 표준적이나 인터셉터·ArgumentResolver 구조를 전면 교체해야 해 회귀 면적이 이번 목적에 비해 지나치게 넓다. 인증 요구가 복잡해지면(OAuth, 리프레시 토큰 회전 등) 재검토한다.
- **SSE 경로 변수 유지 + 토큰 우선** — 클라이언트 무변경이지만 오용 가능한 파라미터가 계약에 남는다.
- **완전 Phase 3b(파라미터 제거)** — 계약이 가장 깨끗하나 클라이언트 3종 동시 릴리스와 오케스트레이터 sign-off가 필요하다.

## 롤백

**단일 커밋이다.** 게이트·소유권·SSE를 각각 분리하려 했으나 셋 다 같은 컴파일 단위로 묶여 있어 불가능했다. 실제로 분리를 시도해 컴파일 실패를 확인했다:

- 수강생 명단 보호가 게이트와 소유권의 교차점이다 — 컨트롤러에 `@Auth`를 넣으면 서비스 시그니처(`getLectureEnrollmentDetail(memberId, lectureId)`)도 함께 바뀌어야 한다.
- SSE는 파일 하나지만 듀얼리드 헬퍼 `AuthIdentities`를 쓰던 마지막 코드였다. 게이트 커밋이 그 클래스를 지우므로, SSE를 빼면 게이트 커밋이 `cannot find symbol`로 빌드되지 않는다.

빌드되지 않는 중간 커밋은 revert 지점으로 쓸모가 없으므로 쪼개지 않았다.

되돌릴 때는 이 커밋 전체를 revert한다. 급한 경우 게이트만 무력화하려면 `AuthConfig`의 등록 한 줄을 제거하면 되지만, 그 상태는 `AuthGateIntegrationTest`가 실패로 잡는다 — 의도적이다.
